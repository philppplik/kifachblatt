Invoker-Render: Weltmodell-Renderer streamt steuerbare Videos

Inclusion AI trennt Weltzustand und Optik: Eine Engine hält die Welt, Invoker-Render rendert sie als Video - 33 Mrd. Parameter, nicht kommerziell lizenziert.

Philipp Paulik, Redaktion KI Fachblatt · mit KI-Unterstützung erstellt, redaktionell verantwortet (so arbeiten wir) · 18. November 2026, 07:15 Uhr · 3 Min. Lesezeit

Kurz gesagt
  • Inclusion AI (Ant Group) hat mit Code World Model 2.0 die Gewichte von Invoker-Render veröffentlicht: ein kausales Streaming-DiT, das strukturelle Proxy-Videos in fertige Optik übersetzt [1][2].
  • Die Architektur teilt die Arbeit: Eine vorgelagerte Engine hält den Weltzustand, grobe Proxy-Videos legen Kamerapfad, Layout und Bewegung fest, Invoker-Render liefert nur das Aussehen [1][2].
  • Das Modell hat 33,12 Mrd. Parameter (FP32, rund 132,5 GByte) und baut auf MiniMax-H3; produktiv empfohlen werden acht GPUs an einem Knoten [1][2].
  • Im Hersteller-Vergleich auf 140 Rollouts liegt Invoker-Render mit einer Elo von 1343,2 vor drei Streaming-Renderern; Trainingsmethode und -daten sind noch nicht veröffentlicht [2].
  • Lizenzfalle: Die Gewichte stehen unter Apache 2.0 UND CC BY-NC 4.0 - kommerzielle Nutzung ist damit ausgeschlossen; nur der eigene Repo-Code ist rein Apache 2.0 [1][2].

Inclusion AI, die KI-Einheit der Ant Group, hat zusammen mit der Westlake University und der Universität Zhejiang Code World Model 2.0 vorgestellt - und damit die Gewichte von Invoker-Render, einem kausalen Streaming-Video-Modell mit 33,12 Milliarden Parametern. Das Hugging-Face-Repository wurde am 16. November angelegt, das Code-Repository am 11. November. Die Grundidee dreht die übliche Video-Generierung um: Nicht das Video-Modell hält die Welt im Kopf, sondern eine vorgelagerte Engine [1][2].

Weltzustand und Optik getrennt

Bei Code World Model 2.0 verwaltet eine upstream Engine den Weltzustand und gibt sogenannte visuelle Proxys aus: schlichte Struktur-Videos, die Kamerapfad, Szenenlayout und Objektbewegungen festlegen, aber keine Optik enthalten. Invoker-Render bekommt ein solches Proxy, dazu ein einzelnes Referenzbild für das Aussehen und einen Text - und rendert daraus die fertigen Frames. Die Proxys dürfen grob oder fein sein: semantische Karten, spärliche 3D-Boxen, Masken, schattierte Geometrie oder Boxen mit Skeletten akzeptiert dasselbe Modell [1][2][3].

Technisch ist Invoker-Render ein kausales Diffusions-Transformer-Modell, das in vier Schritten pro Chunk arbeitet und mit einem stufenweisen Curriculum namens Progressive Forcing trainiert wurde. Basis ist MiniMax-H3, die Inferenz läuft über SGLang und SGLang-Omni. Weil jeder Chunk nur einen festen Optik-Anker und ein begrenztes Verlaufsfenster liest, kann eine Sitzung beliebig lange laufen: Das Team zeigt eine durchgehende 30-minütige Racing-Generierung ohne Schnitt - erzeugt allerdings mit einer Qualitätsrichtlinie, die der Standard-Dienst nicht aktiviert, wie das Repository selbst anmerkt [1][2].

Eckdaten

Gewichte: 33,12 Mrd. Parameter, FP32, rund 132,5 GByte in 29 Safetensors-Split-Dateien, unquantisiert. Achtung bei der Installation: Die mitgelieferte Teacher-LoRA (2,3 GByte, bidirektional, Basis MiniMax-H3) ist ein anderes Modell und darf nicht auf die kausalen Hauptgewichte gestapelt werden. Eingabe: 1344x768 RGB-Startbild, Proxy-Video mit 24 fps Zeitleiste und Text; Datei-Inferenz verlangt 17xN+5 Proxy-Frames, mindestens 39. Betrieb: WebSocket-Sitzungsdienst, Datei- und Browser-Client; das Standard-Profil production nutzt acht NVIDIA-GPUs an einem Knoten. Hinweis der Entwickler: 24 fps ist die Video-Zeitleiste, nicht der Inferenz-Durchsatz [1][2].

Hersteller-Vergleich per Elo

Auffällig ist, was noch fehlt: Der technische Bericht liegt bislang nur als PDF im Repository vor, eine arXiv-Listung steht aus - und Trainingsmethode und Trainingsdaten sind ausdrücklich noch nicht veröffentlicht. Die Elo-Werte stammen also aus einer Hersteller-Evaluierung, deren Protokoll wir nicht im Detail prüfen konnten [2].

Die Lizenzfalle

Die Lizenzlage verlangt einen genauen Blick, weil sie je nach Komponente kippt: Der von Inclusion AI geschriebene Code steht unter Apache 2.0. Die Modellgewichte dagegen unterliegen laut Modellkarte sowohl Apache 2.0 als auch CC BY-NC 4.0 - und die NC-Klausel schließt kommerzielle Nutzung aus. Auch im Code stecken eingebettete Fremdkomponenten, die teils unter CC BY-NC 4.0 stehen; das Repository verweist förmlich auf einen Legal Notice, den man vor Nutzung oder Weitergabe lesen soll. Für Forschung und Demos ist das Paket offen, für Produkte nicht [1][2].

Einordnung

Code World Model 2.0 ist weniger ein Video-Modell als eine Architektur-These: Wenn eine Engine die Welt hält, muss der Renderer keine Physik mehr lernen - er muss nur gut aussehen. Das erinnert an die Pipeline klassischer Game-Engines und macht lange, steuerbare Generierung überhaupt erst planbar. Ob der Ansatz außerhalb der eigenen Demo-Domänen trägt, können erst unabhängige Tests zeigen; die Kombination aus 8-GPU-Bedarf, fehlenden Trainingsdaten und NC-Lizenz begrenzt die Verbreitung vorerst auf Forschung [1][2][3].

Grenzen

Elo-Werte und Demo-Qualität stammen vom Hersteller und sind unabhängig nicht bestätigt; die 30-Minuten-Demo nutzte eine Qualitätsrichtlinie, die der Standard-Dienst nicht aktiviert. Häufige Fragen

Was ist ein visuelles Proxy?

Ein schlichtes Struktur-Video - etwa semantische Karten, 3D-Boxen oder Masken - das Kamerapfad, Szenenlayout und Bewegungen festlegt. Invoker-Render ergänzt daraus plus einem Referenzbild die Optik [1][2].

Ist Invoker-Render ein Weltmodell?

Es ist der Render-Teil von Code World Model 2.0: Eine vorgelagerte Engine hält den Weltzustand, Invoker-Render übersetzt die Proxys der Engine in fertige Bilder [1][2].

Darf ich Invoker-Render kommerziell nutzen?

Nein. Die Gewichte stehen unter Apache 2.0 und CC BY-NC 4.0; die NC-Klausel verbietet kommerzielle Nutzung. Nur der eigene Repo-Code ist rein Apache 2.0 [1][2].

Was brauche ich für den Betrieb?

Das Standard-Profil nutzt acht NVIDIA-GPUs an einem Knoten; dazu kommen weitere Assets (VAE, Textmodell, Decoder), die nicht im Gewichts-Repository liegen. Eigene Tests haben wir nicht durchgeführt [1][2].

Sind die Elo-Werte unabhängig geprüft?

Nein. Sie stammen aus der Hersteller-Evaluierung auf 140 Rollouts; der technische Bericht liegt nur als Repository-PDF vor, arXiv-Listung und Trainingsdaten stehen noch aus [2].
